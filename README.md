# project-self-healing-ci

## What this demo is

This repository demonstrates a GitHub-native, multi-agent self-healing CI pattern shaped around the Sample customer workflow:

1. Normal CI fails and publishes build/test evidence.
2. a Diagnostician coding agent delegates log and diff analysis to native subagents.
3. An independent Policy Gate coding agent validates provenance and decides whether remediation is allowed.
4. Exactly one branch runs:
   - a Remediator coding agent opens the smallest safe healing pull request, or
   - an Escalation coding agent creates an evidence-backed infrastructure escalation without changing code.
5. Unchanged deterministic CI and anti-weakening checks validate a healing pull request.
6. A Validator coding agent publishes readiness for human review and never merges.

Everything runs in GitHub Actions. VS Code is not part of the runtime flow.

## Customer-shaped simulation

The fixtures and agent language mirror relevant Sample concepts:

- core, backend, frontend, agentic, and packaging modules
- Conan/JFrog-style dependency resolution
- build, regression, release-tree, and Coverity-shaped stages
- LSF, NFS, runner, and external-system failure categories

The demo does not connect to live sample-db, LSF, NFS, Coverity, JFrog, JIRA, customer databases, or customer credentials.

## Agent architecture

Repository custom-agent profiles live in `.github/agents/`:

- `sample-diagnostician.agent.md`
- `sample-policy-gate.agent.md`
- `sample-remediator.agent.md`
- `sample-escalation.agent.md`
- `sample-validator.agent.md`

Each `gh-aw` workflow selects one profile through `engine.agent`. Workflows can also define native inline subagents for bounded tasks such as log analysis, diff impact analysis, provenance auditing, test planning, and regression auditing.

The workflow chain is:

```text
CI failure
  -> Sample Diagnose
  -> Sample Policy Gate
     -> Sample Remediate -> healing PR -> Healing PR Validation -> Sample Healing Review
     -> Sample Escalate  -> escalation issue, no code change
```

For branch-originated failures, the remediation workflow aligns its workspace to the triggering workflow-run commit SHA before editing so it can propose a pull request for defects that are not yet on `main`.

Diagnose and Policy Gate exchange versioned, schema-validated artifacts. The two policy outcomes are gated by deterministic jobs before another coding agent can run.

## Deterministic vs contextual components

Deterministic GitHub Actions and policy enforcement:

- `.github/workflows/ci.yml`
- `.github/workflows/healing-pr-validation.yml`
- `tests/policy/`
- `docs/handoff-contracts.json`

Contextual coding agents:

- `.github/workflows/self-heal.md`
- `.github/workflows/self-heal-policy.md`
- `.github/workflows/self-heal-remediate.md`
- `.github/workflows/self-heal-escalate.md`
- `.github/workflows/self-heal-validate.md`

Compiled `.lock.yml` files are generated by `gh aw compile` and must not be edited manually.

## Prerequisites

- GitHub repository with Actions enabled.
- Access to GitHub Copilot Agentic Workflows.
- GitHub CLI 2.0+ authenticated to the repository.
- Official `github/gh-aw` GitHub CLI extension.
- C++17 toolchain.
- CMake 3.20+.
- Conan 2.x.
- Python 3.11+.
- Repository labels `agentic-self-heal` and `abstention`.
- Branch protection and required reviewers configured by a repository administrator.
- For uninterrupted CI on agent-created pull requests, an administrator-provided `GH_AW_CI_TRIGGER_TOKEN`; otherwise a maintainer must use GitHub's **Approve workflows to run** control on the pull request.

make ci
```

This executes:

- `conan profile detect --force`
- `conan install . --output-folder=build --build=missing -s build_type=Release`

```

Commit both the Markdown sources and generated lock workflows. Public-preview syntax may change, so compile with the supported extension version before every workflow change.

## Demo scenarios

### Safe remediation

1. Change `conanfile.py` from `gtest/1.14.0` to a nonexistent version.
2. Open a pull request and observe `CI` fail in dependency installation.
3. Follow Diagnose, Policy Gate, and Remediate runs.
4. Inspect the `agentic-self-heal` pull request and unchanged validation checks.
5. If no CI trigger token is configured, approve the pending GitHub workflow run.
6. Review the Validator agent's readiness comment.
7. A non-author human reviewer approves, then decides whether to merge.

### Infrastructure abstention

Manually dispatch `Sample Diagnose` with `sample-lsf-infrastructure-diagnosis`. Its completion automatically triggers Policy Gate and then the matching outcome workflow. The same contracts drive real failed runs.

The expected result is an `abstention` escalation issue that cites LSF/NFS evidence, recommends `platform-infrastructure`, and explicitly confirms that no code change was created.

## Safety model

- Agents receive read-only repository and Actions permissions by default.
- Writes occur only through bounded safe outputs.
- Handoffs are versioned, validated, provenance-bound artifacts.
- Malformed or ambiguous context fails closed.
- No workflow pushes to or merges the default branch.
- No agent changes credentials, permissions, branch protection, runners, or external infrastructure.
- Existing build, test, static-analysis-shaped, security, and quality checks cannot be weakened.
- Infrastructure failures always abstain until a dedicated policy explicitly allows otherwise.
